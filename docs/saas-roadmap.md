# แผนพัฒนา Trade Sam Where เป็น SaaS

บันทึกวันที่ 22 ตุลาคม 2026 (Asia/Bangkok) เพื่อพัฒนาต่อในวันถัดไป

สถานะ: บันทึกแนวทางและงานที่ต้องทำ ยังไม่ได้พัฒนาระบบ SaaS, เปิดบริการ หรือเปิด Auto รอบใหม่

## เป้าหมาย

ให้ผู้ใช้เข้าเว็บเพื่อตั้งค่ากลยุทธ์ เริ่ม/หยุดบอท และดูผลการทดลอง โดยตัวรันซื้อขายทำงานบนเซิร์ฟเวอร์ต่อได้เมื่อปิดเว็บหรือปิดคอมพิวเตอร์ของผู้ใช้ เริ่มด้วย Simulation และ MT5 Demo ตามข้อจำกัดของระบบปัจจุบัน

การทำงานต่อเนื่องและการรายงานรายวันเป็นคนละเรื่อง: สร้างรายงานตามวันเวลาไทยโดยไม่บังคับปิด Position ตอนเที่ยงคืน ผู้ใช้ต้องกำหนดนโยบายออกจาก Position อย่างชัดเจน เช่น SL/TP, อายุสูงสุดของ Position หรือเวลาปิดเฉพาะ Session โดยยังบังคับข้อจำกัดความเสี่ยง

## แนวทางการเชื่อมต่อ

| ทางเลือก | สิ่งที่ต้องเปิด | ข้อพิจารณา |
|---|---|---|
| SaaS API + MT5 worker | Python และ MT5 บน Windows Server | ต่อยอดของเดิมได้มาก ผู้ใช้ไม่ต้องเปิดเครื่องตัวเอง แต่ยังมีต้นทุนดูแล Terminal และแยกบัญชี |
| SaaS API + Broker API โดยตรง | ตัวรันบนเซิร์ฟเวอร์ที่เชื่อม API ของโบรกเกอร์ | ไม่ต้องใช้ MT5 หาก API รองรับข้อมูลราคา คำสั่ง และเงื่อนไขที่กลยุทธ์ใช้ ต้องตรวจบัญชี สินทรัพย์ และสิทธิ์ API ก่อนเลือก |

แนวทางแนะนำสำหรับ MVP คือ MT5 Demo บน Windows Server หนึ่งบัญชีก่อน พร้อมออกแบบ broker adapter ให้เพิ่ม Broker API ภายหลังได้ นี่เป็นข้อเสนอ ยังไม่ได้เลือกผู้ให้บริการเซิร์ฟเวอร์หรือโบรกเกอร์ใหม่

การทำ REST API ครอบโปรแกรมเดิมไม่ได้เอา MT5 ออก เพราะ Python integration ของ MT5 ใช้ IPC กับ Terminal ส่วนบัญชี MT5 ปัจจุบันไม่สามารถเปลี่ยนไปใช้ API ของโบรกเกอร์อื่นได้โดยอัตโนมัติ

แหล่งอ้างอิง:

- [MetaTrader 5 Python integration](https://www.mql5.com/en/docs/python_metatrader5)
- [MetaTrader 5 startup และการแยก Terminal](https://www.metatrader5.com/en/terminal/help/start_advanced/start)
- [OANDA REST v20 ตัวอย่าง Broker API โดยตรง](https://developer.oanda.com/rest-live-v20/introduction/) — ใช้เป็นตัวอย่างสถาปัตยกรรม ต้องตรวจสาขาผู้ให้บริการ บัญชี และสินทรัพย์ที่รองรับ ไม่ใช่ข้อเสนอให้ย้ายโบรกเกอร์

## โครงสร้างเป้าหมาย

```text
เว็บผู้ใช้
    -> SaaS API: สมาชิก / บัญชี / สิทธิ์ / ค่าความเสี่ยง
    -> ฐานข้อมูลถาวร + คิวงาน
    -> Trading worker: ตรวจสถานะ / กลยุทธ์ / ความเสี่ยง / บันทึกคำสั่ง
    -> Broker adapter
         -> MT5 worker บน Windows
         -> Broker API โดยตรงในระยะถัดไป

Trading worker -> สถิติ / Audit log / Heartbeat / แจ้งเตือน -> เว็บผู้ใช้
```

คำสั่งซื้อขายต้องผ่านการตรวจความเสี่ยงที่ตัวรันอีกครั้ง ข้อมูลรับรองโบรกเกอร์อยู่ฝั่งเซิร์ฟเวอร์และไม่ส่งกลับให้เบราว์เซอร์ ระบบควบคุมกับตัวรันซื้อขายแยกวงจรชีวิตจากกัน

## สิ่งที่นำกลับมาใช้ได้

- กลยุทธ์ การคำนวณ SL/TP และการตรวจความเสี่ยง
- แนวทาง broker adapter เดิม (`SimulationBroker`, `MT5Broker`)
- การติดตาม Position, Journal, สถิติ และเครื่องมือ research/replay
- Request ID และพฤติกรรมไม่ส่งคำสั่งซ้ำเมื่อยังไม่ทราบผล

แอปปัจจุบันเป็น FastAPI/SQLite สำหรับ localhost และบัญชีที่ใช้งานอยู่หนึ่งบัญชี การเปิดให้เข้าผ่านอินเทอร์เน็ตต้องเพิ่มระบบสมาชิกและการแยกข้อมูลก่อน ไม่ควรเผยแพร่ localhost API ปัจจุบันเป็นบริการหลายผู้ใช้โดยตรง

## ลำดับพัฒนา

### 1. ทำตัวรันต่อเนื่องแบบ Demo หนึ่งบัญชี

- [ ] แยกโหมด Session ที่มีเวลาสิ้นสุดออกจากโหมดทำงานต่อเนื่อง คงพฤติกรรม Session เดิมไว้
- [ ] แยกตารางเปิดไม้ใหม่ นโยบายปิด Position และเวลาสรุปรายวัน
- [ ] บันทึกสถานะตัวรันและสิทธิ์การเริ่มใหม่อย่างถาวร ตรวจบัญชี คำสั่งค้าง และ Position ก่อนอนุญาตเปิดไม้หลัง restart
- [ ] ใช้สิทธิ์ถือครอง worker ต่อบัญชีเพื่อป้องกันตัวรันซ้ำ และตรวจผลกับโบรกเกอร์ก่อนจัดการคำสั่งที่ยังไม่ทราบผล
- [ ] เพิ่ม heartbeat, watchdog และการเริ่มโปรแกรมใน Windows user/session ที่เข้าถึง MT5 ได้
- [ ] บังคับเพดานขาดทุนรายวัน เพดาน exposure และ Kill Switch ต่อบัญชีต่อไป
- [ ] ทดสอบ Demo เมื่อ MT5 restart, network ขาด, worker crash, process ซ้ำ และข้ามเที่ยงคืน โดยต้องไม่ส่งคำสั่งซ้ำหรือเริ่มเปิดไม้โดยไม่มีสถานะอนุญาตที่ถูกต้อง

### 2. ทำ SaaS MVP

- [ ] ระบบสมาชิกและการตรวจสิทธิ์ทุกบัญชี/ทุกคำขอ รวมถึงผลลัพธ์งานเบื้องหลัง
- [ ] แยกข้อมูลสมาชิก บัญชี กลยุทธ์ ค่าความเสี่ยง คำสั่ง และสถิติ ใช้ฐานข้อมูลที่เหมาะกับหลาย worker เช่น PostgreSQL
- [ ] แยก API ออกจาก trading worker และมีคิวงานถาวร โดยการรับงานซ้ำต้องไม่ทำให้ส่งคำสั่งซ้ำ
- [ ] เก็บข้อมูลรับรองแบบเข้ารหัสหรือผ่าน secret store พร้อมการเปลี่ยน/เพิกถอนสิทธิ์ และปิดบังข้อมูลใน log
- [ ] หน้าเว็บแสดงสถานะจริงของ worker, การเชื่อมต่อ, Position, ผลเทรด และปุ่มหยุดรายบัญชี
- [ ] เพิ่มการสำรอง/กู้คืนข้อมูล การติดตามเหตุการณ์ และการแจ้งเตือนเมื่อจำเป็นต้องให้ผู้ดูแลตรวจ
- [ ] ทดลองหนึ่งบัญชี Demo ก่อน แล้วพิสูจน์การแยกข้อมูลและทรัพยากรด้วยหลายบัญชี Demo

### 3. ประเมิน Broker API โดยตรง

- [ ] ตรวจโบรกเกอร์ สาขาที่ให้บริการ บัญชี และสินทรัพย์ที่ต้องการ รวมถึงสิทธิ์ใช้งานเชิงพาณิชย์
- [ ] เทียบรูปแบบบัญชี, hedging/netting, SL/TP, pending orders, lot/tick size, margin, swap, ประวัติราคา และ rate limits กับสมมติฐานของกลยุทธ์
- [ ] พัฒนา adapter แยกจาก MT5 และทดสอบกับ Sandbox/Demo ก่อนใช้งานจริง

ยังไม่รวมการเปิดบัญชีจริง การรับเงินลูกค้า การเรียกเก็บค่าสมาชิก หรือการประกาศว่ากลยุทธ์ทำกำไรได้

## สถานะงานเดิมสำหรับรับช่วง

รอบทดลองล่าสุดสิ้นสุดตามเวลาแล้วและไม่ได้สั่งเริ่มใหม่ในงานบันทึกแผนนี้ ตัวรันเดิมจำกัด Session ไม่เกิน 24 ชั่วโมง และไม่เปิด Auto เองหลัง crash/restart จึงยังไม่ใช่ระบบ 24/7

งานที่พัฒนาในรอบ Demo และเก็บใน Git:

- เพดานจำนวนไม้รวมต่อ Session แยกจากจำนวนถือพร้อมกัน (`max_trades: null` คือไม่จำกัดจำนวนรวม)
- ตัวรัน `trade_app/demo_session.py` และสถิติตามวงจร Position ใน `trade_app/session_stats.py` รวม exit หลังข้ามวัน
- ทิ้ง IPC handle เก่าและเว้นช่วงเชื่อมต่อ MT5 ใหม่ โดยไม่ retry คำสั่งซื้อขายที่ยังไม่ทราบผล
- การตั้งค่า timestamp offset อย่างชัดเจนโดยไม่เดาอัตโนมัติ และการปฏิเสธ quote ในอนาคต
- ตรวจ quote coverage ของ replay และแยก fold ที่ข้อมูลไม่ครบออกจากผลที่นำมาประเมิน
- แก้ final research ให้ใช้ balance และ settings ตอนเริ่ม Session แทนสถานะหลังปิดรอบที่เปิด Kill Switch แล้ว

ข้อจำกัดที่ต้องตามต่อ:

- ผล Demo เพียงสองรอบยังไม่พอประเมินความสามารถทำกำไรหรือผลของการถือจน SL/TP
- Replay ยังมีบางสัญญาณถูกปฏิเสธจากราคา SL/TP ที่ไม่ได้ปัดตาม tick size ต้องแก้และตรวจเทียบกับเส้นทางส่งคำสั่งจริงก่อนใช้เปรียบเทียบกลยุทธ์
- ทดสอบแบบ shadow ด้วยจุดเข้าเดียวกันเพื่อเปรียบเทียบการปิดเที่ยงคืนกับ SL/TP และอายุถือสูงสุด โดยบันทึก swap/ต้นทุนและการปิดที่ยังไม่ทราบผล
- Offset เวลา MT5 ที่ตรวจพบใช้ได้กับช่วงที่ตรวจเท่านั้น ต้องยืนยันใหม่เมื่อเปลี่ยนโบรกเกอร์หรือ DST
- ฐานข้อมูล บัญชี รายงานดิบ และ log อยู่ใต้ `data/` เฉพาะเครื่อง ถูก ignore และไม่ได้สำรองด้วย GitHub

## เริ่มงานครั้งถัดไป

1. อ่านไฟล์นี้และ `docs/dashboard.md`, `docs/research.md` ตรวจ `git status` ก่อนแก้ไข
2. ตรวจว่าต้องการเริ่มขั้นที่ 1 แบบ Demo บัญชีเดียวตามข้อเสนอ หรือเลือก Broker API โดยตรงก่อน
3. กำหนดนโยบายเปิดไม้/ออกจาก Position/เริ่มใหม่หลัง restart แล้วทำตัวรันต่อเนื่องและทดสอบความล้มเหลวก่อนเพิ่มระบบสมาชิก
4. รันชุดตรวจพื้นฐานจาก README; อย่าใช้ไฟล์แผน Session เก่าที่หมดเวลาเพื่อเริ่ม Auto ใหม่

บันทึกแผนและ push โค้ดครั้งนี้ไม่ได้เป็นการเริ่มทดลองซื้อขายรอบใหม่
